Selenite is a self-hosted web proxy built on top of [Ultraviolet](https://github.com/titaniumnetwork-dev/Ultraviolet) by TitaniumNetwork. It runs entirely in the browser using service workers and an encrypted WebSocket transport, letting users browse the open web from behind restrictive networks — with no client-side software required.

Deploy it to any Node.js host in minutes, protect access with per-domain passwords, and customise the look with 16 built-in themes.

## What Selenite Does

Selenite intercepts browser requests through a registered service worker and tunnels them via an encrypted [Wisp](https://github.com/MercuryWorkshop/wisp-protocol) WebSocket connection. The server rewrites URLs under the `/purple/service/` prefix so that the origin site never appears in the browser address bar and network-level filters cannot identify or block the traffic.

## Get Started

<Steps>
  <Step title="Clone and install">
    Clone the repository and install Node.js dependencies with npm. There is no separate build step.

    ```bash
    git clone https://github.com/selenite-cc/proxy.git
    cd proxy
    npm install
    ```
  </Step>
  <Step title="Create a password file">
    Create `src/api/some.pass` with a JSON object mapping each domain to its password. Both `addPass.cjs` and `verify.cjs` read this file from `src/api/some.pass`.

    ```json
    {
      "yourdomain.example": "your-secret-password"
    }
    ```
  </Step>
  <Step title="Set the environment variable">
    Copy `.env.example` to `.env` and set `ADD_LINK_PASS` to the secret used to authorise calls to the `/api/addLink` management endpoint.

    ```bash
    cp .env.example .env
    # Edit .env and set ADD_LINK_PASS=your-api-secret
    ```
  </Step>
  <Step title="Start the server">
    Run `npm start` to launch the server, then open `http://localhost:8080` in a Chromium-based browser.

    ```bash
    npm start
    ```
  </Step>
</Steps>

<Note>
  Service workers require HTTPS on any hostname other than `localhost` or `127.0.0.1`. When testing locally those two hostnames are explicitly allowed over plain HTTP, so any modern browser — including Firefox — will work. For any other domain you must serve Selenite over HTTPS.
</Note>
