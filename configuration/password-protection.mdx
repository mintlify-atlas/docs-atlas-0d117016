Selenite supports per-domain password protection out of the box. Passwords are stored in a single JSON file — `src/api/some.pass` — and the server watches that file for changes so you can add, update, or remove passwords at any time without a restart. Every incoming HTTP request is checked for a valid password cookie before the proxy or any static asset is served.

## How the password file works

Passwords live in `src/api/some.pass` as a plain JSON object that maps each hostname to its required password:

```json
{
  "yourdomain.com": "yourpassword",
  "another.domain.net": "anotherpassword"
}
```

Both `src/api/verify.cjs` and `src/api/addPass.cjs` open this file at startup and register an `fs.watch` listener on it. Whenever the file changes on disk, the in-memory `passwords` object is refreshed immediately — no server restart needed.

```js
// src/api/verify.cjs (simplified)
fs.watch(filePath, () => {
  fs.readFile(filePath, "utf8", (err, data) => {
    if (err) { console.error(err); return; }
    try {
      passwords = JSON.parse(data);
      console.log("file change");
    } catch (err) {
      console.error("Error parsing JSON:", err);
    }
  });
});
```

<Tip>
  Use a strong, randomly generated password for each domain. Because the
  prompt-based login sends the password as a plain cookie value, an attacker who
  can observe unencrypted traffic could capture it. Unique per-domain passwords
  limit the blast radius of any single credential being compromised.
</Tip>

## How authentication is enforced

Every request passes through an Express middleware that calls `checkPass(req)` before any static files or proxy routes are reached:

```js
// src/index.js
app.use((req, res, next) => {
  if (!checkPass(req)) {
    res.send(
      "<script>document.cookie = `password=${prompt('Enter the password')}`;location.reload();</script>"
    );
  } else {
    next();
  }
});
```

`checkPass` reads the `password` cookie from the incoming request and passes it to `isPassValid`, which compares it against the entry for `req.hostname` in the `passwords` map:

```js
// src/api/verify.cjs
function isPassValid(pass, website) {
  try {
    return passwords[website] == pass;
  } catch {
    return false;
  }
}

function checkPass(req) {
  let cookies = get_cookies(req);
  if (cookies["password"]) {
    return isPassValid(cookies["password"], req.hostname);
  } else {
    return false;
  }
}
```

When no valid `password` cookie is present, the server responds with an inline `<script>` that calls `window.prompt`, stores the entered value in the `password` cookie, and reloads the page. The cookie name is literally `password`.

<Warning>
  The browser `prompt()` flow sends the password as a plain-text cookie value.
  This is **not encrypted in transit** unless you are running Selenite behind
  HTTPS. Always use a valid TLS certificate in production — without it, the
  password can be intercepted by anyone on the network path.
</Warning>

## Adding passwords via the API

The `POST /api/addLink` endpoint lets you add new domain→password entries programmatically without editing `some.pass` by hand. It is guarded by `canAddLink`, which compares the `auth` field in the request body against the `ADD_LINK_PASS` environment variable:

```js
// src/api/verify.cjs
function canAddLink(req) {
  if (req.body.auth) {
    return req.body.auth == process.env.ADD_LINK_PASS;
  } else {
    return false;
  }
}
```

A valid request looks like this:

```bash
curl -X POST https://yourdomain.com/api/addLink \
  -H "Content-Type: application/json" \
  -d '{"auth": "your-ADD_LINK_PASS-value", "link": "newsite.example.com", "password": "sitepassword"}'
```

`addPass` writes the updated object back to `some.pass` with `fs.writeFileSync`, which then triggers the `fs.watch` callback and refreshes the in-memory map instantly.

## Checking whether a domain is password-protected

The `GET /check?domain=<hostname>` endpoint returns `200` if the given domain has an entry in `some.pass`, or `404` if it does not:

```bash
curl "https://yourdomain.com/check?domain=another.domain.net"
# 200 OK  — entry exists
# 404 Not Found — no entry
```

This endpoint does not require authentication and can be used by frontend code to decide whether to show a login prompt before attempting a proxied request.
